# 汇总规则与输出模板

## 固定三列

第一列“床号”，第二列“时间、情况与处理”，最后一列“消息来源”。不再拆出处理、结果或待办列。每床一行，按床号升序；全部配置床位均保留。

下面是虚构格式示例，不是实际患者记录：

```markdown
### 2026-10-27 病人每日情况汇总（供核对）

统计时段：2026-10-27 07:00 至 2026-10-28 07:00（北京时间，含起点、不含终点）
读取情况：按实际读取结果逐来源说明，不预填成功或消息条数。

| 床号 | 时间、情况与处理 | 消息来源 |
| -- | -- | -- |
| 3床 | ① 10-27 11:42 记录恶心；11:44 医生回复“好”，未见明确处置或执行记录。[1][2]<br>② 10-27 19:50 再次记录恶心，未见后续处理反馈。[3]<br>③ 10-28 06:20 记录已完成采血。[4] | [1] 医护群 10-27 11:42<br>[2] 医护群 10-27 11:44（引用①）<br>[3] 医护群 10-27 19:50<br>[4] 指定私聊 10-28 06:20 |
| 9床 | 未检索到相关记录（不代表无异常）。 | 已核查的来源名称与统计时段 |

待确认信息：仅列实际存在的归属不明、冲突、缺失或图片内容无法识别等问题；无则省略。
```

## 分点、关联与顺序

- 第二列每点用 `①`、`②` 等编号，以 `<br>` 换行，不能用一长段或仅用分号代替分点。单元格中原文 `|` 转义为 `\|`。
- 情况与处理明确属于同一事件时写在同一点，分别保留时间，例如“10-27 20:02 发热38.2℃；20:05 医生建议暂停输注（未见执行确认）；20:12 护士记录已暂停”。明确的后续结果也可附在这一点。
- 关联证据优先使用引用回复、同床号且明确指向该事件的文字；紧邻上文仅在唯一、无歧义且内容相符时可用。不能仅因为时间相近、同一床号或医学上可能相关就配对。
- 无法与某次情况匹配的处置独立列点，不强配原因。复发或新的独立事件另列一点。
- 各点按最早事件时间排序；点内按情况、处理、反馈的实际时间排序。关联处理即使晚于其他独立事件，也保留在原事件点内，并保留准确时间，不能改造为全局严格时间流。
- 每点首时间用 `MM-DD HH:MM`，跨日期的后续处理也写日期，同日点内可只写 `HH:MM`。不写模糊时间范围代替各时间点。
- 消息明确写了实际发生时间，优先记录发生时间；否则写“MM-DD HH:MM 消息记录：……”，不能把发送时间冒充发生时间。时间不详就标明“不详/待核实”，不补造。
- 窗口按消息发送时间筛选；窗口内消息追述旧事件时，注明真实事件日期及“追述”。引用窗外消息只作背景，不把引用内容当作本窗口新发生事件。

## 来源可追溯

每点用 `[1]` 等标记对应最后一列的来源名称和消息日期时间；同一点涉及多条消息或多个来源，逐一列出。可附原始消息 ID（抓取提供时），不捏造 ID、链接、条数或发送人。跨来源同一事件可去重合并，但保留补充信息和全部证据来源。来源冲突须如实并列、标“待核实”，不自行选定一个版本。

## 床号归属

识别“2床”“2某某”、@提及、引用回复等。纯答复“已开”“收到”“不泵了”必须有可确认的归属证据。一条消息涉及多床，只摘录目标床位部分。

姓名辅助匹配仅限本次记录中已有明确且唯一的床号关系。出现同名、换床、出院后新患者、归属冲突时，不自动合并；列入待确认，不泄露姓名。患者更替明确时，同一床号行内标明“更换患者前/后”并分组，避免把前后病例串成同一事件。

## 处理状态与事实

- “建议给药/半只速尿”只是建议或医嘱，写“建议/待执行”，无确认就写“未见执行确认”。
- “已开”只代表已开医嘱，不代表已经给药；“收到/好”只代表答复，不代表开医嘱或执行。
- 明确“已给药/已暂停/输完”才按原文写对应动作已执行，不能从一个动作推断所有处置完成。
- 不推断诊断、处置原因、疗效；“后续体温下降”不能自行改为“用药有效”。没有结果可写“未见后续反馈”，不是“无效”。
- 保留原文重要数值、单位、药名、剂量、频次和时间。原文缺失或含糊则注明待核实，不换算“半只”为具体毫克。
- 图片、语音或其他无法读取的附件，只说明“内容未能识别”，不猜测。
- 没有记录写“未检索到相关记录”；来源失败写“记录不完整/无法判断”，不能写患者无异常。

## 读取情况和未完成报告

表格前按来源说明成功、无消息或失败。只在抓取有准确统计时引用条数，区分全部消息条数与目标床位事件数。

部分来源失败时，临时草稿必须醒目标明缺失来源和范围，不能标为最终完整日报，不能调用 `complete`；可保存为 `<统计日期>.partial.md`。全部失败时仅说明失败，不编造患者表格。保留待补运行状态。

表后可列“待确认信息”和聊天明确提出的未完成交接事项，不另行生成治疗建议，也不为凑版面重复全部表格。
