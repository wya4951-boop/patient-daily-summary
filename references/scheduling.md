# WorkBuddy 调度与补运行

本文件说明如何连接宿主调度器；技能本身不是常驻进程。用户仅要求修改技能时，不创建任务，不声称已启用。

## 触发与恢复

使用 WorkBuddy 实际可用的自动化工具，先查询同一技能已有任务并更新，避免重复创建。时区 Asia/Shanghai。

1. 主触发：每天07:00。
2. 恢复触发：优先使用宿主提供的启动/恢复后补执行能力；若没有，增加每15分钟一次的补运行检查。必须运行 `plan`，只有 `due` 才抓取与汇总，`complete` 或 `not_due` 静默退出。
3. 配置同一技能任务不并发。每次抓取最多600秒；一次失败交给下一次检查，不在单次任务内无限重试。
4. 每次恢复均重新计算当日窗口，不能重放队列中的过期日期。07:00前不追补更早日报；07:00后只处理前一日07:00至当日07:00。
5. 应用未运行、电脑关闭或模型/网络不可用时，技能无法自行唤醒。只有调度宿主可运行时才能检查并补跑；未确认宿主恢复能力时，不承诺恢复瞬间完成。每15分钟检查代表最迟在下一次可运行检查时尝试。

不要只注册 PowerShell 抓取脚本：这只能导出聊天，不能生成语义汇总。调度任务必须唤起可以读取本技能并生成表格的 WorkBuddy 助手。没有可用自动化接口时，提供下面的任务正文与上述设置供用户在 WorkBuddy 配置；不要改动未知的内部数据库。

## 自动化任务正文

读取 <本机技能安装目录>/SKILL.md、用户目录下 .workbuddy/patient-daily-summary/config.json（不存在则使用技能内空白模板）和 references/summary-rules.md，并严格按当前文件执行，勿固化床位或会话清单。先运行 scripts/run_daily.ps1 -Action plan。若返回 status=unbound，不做任何抓取，首次提示用户按 references/binding.md 绑定床号与会话来源后结束；未绑定状态不变时不反复通知。按北京时间只处理前一日07:00（含）至当日07:00（不含）；当日07:00尚未到或报告已完整生成时静默结束。当天缺少完整报告时执行 -Action scrape，读取本次返回的 raw，按床号生成“床号｜时间、情况与处理｜消息来源”三列表格；每床分点，同一事件的情况和处理可合并并保留各时间，否则按时间排列，逐点对应来源。核对所有来源和执行状态后保存到 plan 指定的 report，再执行 -Action complete。抓取、模型处理、来源完整性或保存失败均不得登记完成，下一次检查继续尝试；不自动追补更早日期，不把旧latest.md当成本次结果。不发送邮件或群消息。成功时向用户提供报告；状态不变时保持安静，仅有新失败、恢复完成或需要用户操作时通知。

任务正文不得写入床号、群名、wxid：这些只从 config.json 读取，床位或来源变更后无需改任务。

## 验证后再宣布启用

检查调度器返回的实际时间、时区、重试/恢复行为和任务启用状态。只有全部配置成功，才将用户目录下个人配置的 schedule.scheduler_configured 改为 true，并告知用户实际生效情况。配置字段仅是登记信息，不控制宿主任务；之后变更07:00时点或重试间隔，需要同时更新宿主调度配置。床位或来源变化无需修改任务正文，下一次读取配置生效。
